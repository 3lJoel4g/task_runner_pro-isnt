# INC-001: Merge accidental de feat/hito-1-rf-11-poll a main

## Fecha
2026-10-08

## Detectado por
Auto-reporte del desarrollador tras revisar la topología con git log.

## Severidad
Baja.

## Descripción
Al terminar el Paso 1.1 del Hito 1 (refactor de RF-11 con poll()),
la rama `feat/hito-1-rf-11-poll` se mergeó por error directamente a
`main` mediante el PR #8, en lugar de pasar por `develop` y esperar
el cierre de la Quality Gate G1.

## Causa raíz
1. Ausencia de branch protection en `main` y `develop`.
2. Hábito reciente de hacer merges directos a `main` (heredado del
   saneamiento de Hito 0, donde fue puntualmente necesario).
3. No se siguió el flujo declarado: feat/* → develop → main.

## Impacto
- `origin/main` contiene el commit de RF-11 antes de que G1 esté
  formalmente cerrado (RF-01 y RF-02 siguen pendientes).
- `develop` quedó rezagado y desincronizado respecto a `main`.
- Sin pérdida de código ni corrupción.

## Acción correctiva aplicada
Estrategia conservadora (B1):
- `main` no se reescribe (es rama pública, RNF-33).
- `develop` se sincronizó con `origin/main` mediante fast-forward,
  quedando alineadas.
- El cierre formal de G1 se hará cuando RF-01 y RF-02 estén
  verificados.

## Acción preventiva
1. Activar branch protection en `main` y `develop`:
   - Require pull request before merging.
   - Require status checks (cuando exista CI).
   - Do not allow bypassing.
   - Force pushes y deletions desactivados.
2. Regla operativa: los PR de trabajo apuntan SIEMPRE a `develop`.
   Los PR de `develop → main` se abren solo al cierre de un Hito/Gate.
3. Checklist antes de cada PR:
   - `git branch --show-current` → confirmar rama actual.
   - `git log --oneline -3` → revisar commits.
   - Verificar la rama base del PR en la UI de GitHub.

## Trazabilidad
- Afecta al flujo definido en `README.md` y `project-management/roles.md`.
- Vinculado a RNF-33 (trazabilidad y control de cambios).
