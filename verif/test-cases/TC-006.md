# TC-006: Captura separada de stdout/stderr (RF-11) y propagación de exit code (RF-07)

## Requisitos cubiertos
- RF-07: registrar marcas de tiempo y código de salida.
- RF-11: captura separada y no mezclada de stdout y stderr.

## Precondiciones
- Binario `src/server` compilado con `-Wall -Wextra -Werror -std=c++17`.
- `bash` disponible en el PATH.

## Procedimiento
1. Ejecutar `make -C src test`, que orquesta `verif/scripts/tc-006.sh`.
2. Caso 1 — captura básica:
   `./src/server bash -c 'echo OUT-LINE; echo ERR-LINE 1>&2'`
   Verificar que stdout contiene `OUT-LINE` y stderr contiene `ERR-LINE`.
3. Caso 2 — estrés de I/O concurrente (deadlock original):
   `./src/server bash -c 'yes ... | head -n 20000; yes ... | head -n 20000 1>&2'`
   Cada stream supera ampliamente `PIPE_BUF` (~64 KiB).
   Verificar que el servidor termina en < 15 s y captura ambas salidas.
4. Caso 3 — propagación de exit code:
   `./src/server bash -c 'exit 42'`
   Verificar que el binario `server` retorna 1 (job fallido), no 0.

## Resultado esperado
- Caso 1: OUT y ERR capturados en campos separados del reporte.
- Caso 2: el servidor termina sin bloqueos; ambos streams capturados íntegros.
- Caso 3: exit code del servidor refleja el fallo del job.
- `make test` termina con `PASS=1 FAIL=0`.

## Criterio de aceptación
Los 3 casos pasan y la evidencia queda registrada en
`verif/results/<run-id>/tc-006.log`.

## Trazabilidad
- RF-07, RF-11
- RNF-08 (aislamiento de fallo, no bloqueo del servicio)
- ADR-0002 (modelo de concurrencia e IPC)
- AI-usage entrada 001 (rechazo del diseño original)
