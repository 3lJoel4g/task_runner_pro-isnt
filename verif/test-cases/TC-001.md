# TC-001: Aceptar trabajo con argumentos y validar la solicitud

## Requisitos cubiertos
- RF-01: aceptar envío de comando con argumentos y retornar ID único.
- RF-02: validar solicitudes; rechazar vacías o malformadas con mensaje útil.

## Precondiciones
- Binario `src/server` compilado con `-Wall -Wextra -Werror -std=c++17`.
- `bash` disponible en el PATH.

## Procedimiento
1. `make -C src test` ejecuta `verif/scripts/tc-001.sh`.
2. Caso 1: `./src/server echo hola`. Espera exit 0, SUCCEEDED, ID 1.
3. Caso 2: `./src/server bash -c 'exit 7'`. Espera exit 1 del servidor,
   estado FAILED y `exit_code : 7`.
4. Caso 3: `./src/server` (sin args). Espera exit 2 y mensaje de uso.
5. Caso 4: `./src/server ""` (comando vacío). Espera exit 2 y mensaje
   mencionando "vacío".
6. Caso 5: `./src/server /ruta/que/no/existe`. Espera exit 1 del servidor,
   estado FAILED y `exit_code : 127` (convención `_exit(127)` tras execvp fallido).

## Resultado esperado
Los 5 subcasos pasan. Cada caso deja su log en
`verif/results/<run-id>/tc-001.log`.

## Criterio de aceptación
`make test` termina con `PASS=2 FAIL=0` (TC-001 + TC-006).

## Trazabilidad
- RF-01, RF-02, RF-07
- RNF-17 (mensajes informativos), RNF-19 (suite con un comando)
- ADR-0002 (modelo de concurrencia e IPC)
